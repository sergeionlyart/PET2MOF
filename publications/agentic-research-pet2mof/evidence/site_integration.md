# Перенос статьи на Dobrovola.dev — записка по интеграции

**Статус:** черновик для согласования. Разрешений на запись в репозиторий сайта, Preview, production, CI и
публикацию нет (поручение TASK-004 §12). Эта записка описывает, как комплект ложится на существующий порядок
импорта сайта; сама интеграция не выполнялась.

## Версия шаблона

Сверка выполнена по приватному репозиторию сайта, `main` = `b4a57048d32148707e81bb373088c6003b342b67` (совпадает с
указанным в поручении), и по двум опубликованным RU-статьям того же шаблона. Код, стили и тексты сайта в PET2MOF не
копировались: таблица стилей `index.html` написана заново по токенам из поручения (цвета, ширины 740/1380 px) и
измерениям публичных страниц. Для русской локали сайт использует системные шрифты (Georgia для чтения, Helvetica
Neue/Arial для интерфейса, системный monospace), поэтому автономная страница визуально близка к нативной; точное
совпадение шаблона не заявляется — его покажет только штатный рендер сайта.

## Что передаётся

| Файл | Назначение на сайте |
| --- | --- |
| `article.ru.md` | UTF-8 Markdown-источник; YAML-блок в начале (subtitle, slug, lang, author, date, revision, status, description), первый H1 → `title` |
| `article.metadata.json` | данные для паспорта публикации (агент сайта формирует паспорт сам) |
| `assets/fig0N_*.png` | изображения статьи (PNG, каждое < 10 MiB; весь пакет < 50 MiB) |
| `assets/fig0N_*.svg` | редактируемые исходники схем; на сайт не загружаются (SVG не принимается как растровое изображение) |
| `prompts/*.md` | полные очищенные тексты промптов (они же — в приложении статьи) |

## Соответствие разметки

* Использовано только поддерживаемое подмножество: H2/H3, абзацы, strong/emphasis, inline code, HTTPS- и
  якорные ссылки, простые списки без вложенности, fenced code, простые pipe-таблицы, изображение отдельной строкой с
  курсивной подписью в следующей строке (→ штатная figure-директива). Сырого HTML, вложенных списков, MDX нет.
* **Раскрываемые промпты.** На сайте нет раскрываемых блоков в Markdown. В источнике приложения — обычные разделы
  `## Приложение …` с подразделами `###`; автономный `index.html` показывает каждый такой `###` как `<details>`, при
  печати все раскрыты. На сайте эти подразделы будут обычными H3 (длинное приложение), либо нужен отдельный
  allow-listed компонент — это решение платформы, код сайта не менялся.
* **Формула** записана fenced-блоком `text` с пояснением словами; MathML/CDN не требуются.
* **Ссылки.** На материалы проекта — только immutable GitHub URL трёх опубликованных commit PET2MOF. Внешний контекст (раздел о Гданьске и системе залога) — пять публичных HTTPS-страниц, список и дата обращения в `evidence/source_versions.json` и `claims.csv` C31–C38; это не постоянные адреса, перед публикацией их стоит перепроверить. Внутренние — якоря на
  заголовки. Идентификаторы заголовков `index.html` формирует сборщик статьи; генератор якорей сайта может давать
  другие id — внутренние ссылки «#…» нужно сверить после импорта.
* **Относительные ссылки на файлы** (`prompts/…`) в статье не используются: импортёр их не поддерживает.

## Не выполнено

* **Пробный прогон импортёра сайта не выполнялся** (запрещена запись в репозиторий сайта и запуск его инструментов
  в рамках поручения); совместимость проверена по документации импорта и нашим проверкам `tools/check.py`.
* Не проверено, принимает ли импортёр fenced-блоки с четырьмя обратными кавычками (если они понадобятся для
  промптов, содержащих тройные кавычки).
