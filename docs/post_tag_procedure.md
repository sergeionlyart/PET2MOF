# Процедура после prereg-v1

Назначение: выполнить замороженную цепочку без смены HEAD, раскрыть наблюдения
только после сохранения прогнозов, отдельно отчитаться о полных/условных сравнениях.
Все команды выполняются локально из корня checkout. GitHub/внешняя CI не используется.
Независимая приёмка T021 и решение руководителя должны предшествовать **настоящему**
тегу; T020 создаёт тег только в отдельном временном клоне с синтетическими данными.

## 1. Подготовка руководителем до тега

Включить принятые код, конфигурации, пояснения D-18 и итоговый
`configs/frozen_parameters.yaml` в один проверенный commit. Все требуемые C-серии
имеют статус verified; два NIST-дополнения S100 с неизвестными ошибками исключены.
Устаревший provisional-файл удалён; чувствительность при необходимости создаётся
заново явным `--include-provisional`, не используется для основного прогноза.

```sh
export UV_CACHE_DIR="$PWD/.uv-cache"
uv sync --locked
make test
uv run --locked --no-sync python scripts/calibrate_final.py
git diff --exit-code -- configs/frozen_parameters.yaml
```

Побайтовый diff должен быть пуст. После принятия и разрешённых руководителем
commit/tag — в замороженном checkout:

```sh
test "$(git rev-parse HEAD)" = "$(git rev-parse 'prereg-v1^{commit}')"
test -z "$(git status --porcelain --untracked-files=all)"
```

Не вливать и не checkout-ить ветку `holdout/v1` в этом checkout: merge/commit
нарушит exact HEAD. Ветка остаётся отдельным хранилищем извлечения, а файлы
передаются локально. Любая поправка модели после раскрытия требует новой версии
и пересмотра независимости проверки; перезаписывать исходный прогноз нельзя.

## 2. Полное воспроизведение до передачи наблюдений

```sh
make reproduce-full
```

Команда требует чистое дерево и exact тег, пересчитывает C с 64 совместными
подгонками и проверяет побайтовое совпадение YAML с HEAD. Затем выполняет
360 отдельных ветвей, каждая по 4×4096, seeds 12001–12004. Продуктивный режим
отказывается от других N/repeats/seed или ограниченного числа ветвей.
Автоматического увеличения N нет (D-18). Невыполненная/неопределимая сходимость —
`not_established`, без решающего научного вывода.

### Основной ансамбль H1/H1a: номинальные условия

Все выборки каждой ветви используют одни и те же управляющие условия из
`configs/scenarios.yaml` (`ads` и `nominal_controls`), заданные в `model_spec.md` §6:
адсорбция 308.15 K, 1 бар, 5% CO2 на сухой базе; R1 — 383.15 K, 1 бар,
`y_CO2=y_H2O=0.001`; R2 — 363.15 K, 0.10 бар, `y_CO2=y_H2O=0.01`;
остаток продувки N2, обе стадии по 1800 с. RH=0/40/70% сравниваются отдельно.
Неизвестные свойства материала, включая времена релаксации, продолжают
варьироваться; выдержки и граничные газовые условия не варьируются.
Это применение неизменных гипотез и протокола §6, без смены критериев.

Отчёт содержит `analysis_role=nominal_H1_H1a`, `fixed_controls`, `RH_percent`;
`fixed_controls` повторяются в отчёте каждой ветви. В `samples.npz` постоянные
управляющие условия сохранены в `parameter_names`/`parameters` каждого повтора
вместе с варьируемыми свойствами материала. Ранги и интервалы относятся только
к указанным номинальным R1/R2.

### Отдельная чувствительность к режимам (не решающая)

Вариации температур, давления R2, примесей и выдержек из `screen_bounds`
относятся к отдельному `revision_screening.screen_revision`, выход
`reports/T015/screen.json`. Этот debug-скрининг отмечается
`analysis_role=control_sensitivity`, `hypothesis_decisions_applicable=false`.
Основной отчёт ссылается на него полем `control_sensitivity` с `decisive=false`;
`status=separate_analysis` не означает новый выполненный прогон скрининга.
Его диагностические вероятности/интервалы не объединяются с основным ансамблем
и не являются дополнительными попытками принять H1/H1a.

Выходы: `runs/<run_id>/passport.json`, `reports/ensemble/summary.json`,
карты/таблицы и `SHA256SUMS.large`; большие `*.npz` игнорируются Git.
Логи — `private/run_logs/<run_id>/`. При отказе сохраняется паспорт и причина;
повтор не заменяет отрицательный результат. Статус/exit code паспорта проверяют
вместе с выводом команды. Отчёт ансамбля остаётся условным прогнозом.

## 3. Передать только условия и сохранить прогнозы

Проверяющий передаёт `conditions.csv` по `docs/holdout_schema.md` **без q**.
Если условия хранятся в отдельной локальной ветке извлечения, возможна адресная
передача без смены HEAD (команду выполняет руководитель/проверяющий после тега):

```sh
git archive holdout/v1 holdout/v1/conditions.csv | tar -x -C .
uv run --locked --no-sync python scripts/predict_holdout.py
```

Весь каталог `holdout/v1/` игнорируется: условия, прогнозы и наблюдения не грязнят
дерево. Каталоги `reports/ensemble/`, `reports/validation/` и **новые**
`runs/<run_id>/` также игнорируются; ранее отслеживаемые исторические паспорта
остаются отслеживаемыми. Исключения добавлены до тега, а не локальной правкой
научных файлов после него. Если такой файл уже отслеживается в принятом commit,
`.gitignore` не скроет его изменение — это следует устранить до тега.

`scripts/predict_holdout.py` читает только frozen C и условия, не наблюдения.
Сохранить неизменными `predictions.csv`, `model_derivatives.csv`,
`prediction_metadata.json`; перед раскрытием проверяющий независимо фиксирует
время/порядок передачи и хеши этих файлов. SHA-256 сам по себе не доказывает
порядок раскрытия; требуется независимая декларация проверяющего.
Полный пакет обязателен: отсутствие любого из трёх файлов останавливает проверку.
Каждая строка прогнозов имеет `run_status=frozen_prediction`, метаданные —
`status=frozen_prediction` и SHA тега. Четыре внутренних SHA-256 метаданных
(`conditions_sha256`, `parameters_sha256`, `prediction_sha256`, `derivatives_sha256`)
сверяются соответственно с `conditions.csv`, `configs/frozen_parameters.yaml`,
`predictions.csv`, `model_derivatives.csv`. При повторе сохранять прежний
пакет отдельно, не перетирать зафиксированные прогнозы.

## 4. Раскрытие и freeze.json проверяющим

Только после сохранения прогнозов передать `observations.csv`, например
адресным `git archive holdout/v1 holdout/v1/observations.csv | tar -x -C .`.
Проверить единицы, массовую базу, comparable/inputs_known, ошибки извлечения,
отсутствие экспериментального 3 %-пола внутри `u_dig` и происхождение шкалы.
Все `u_*` — стандартные неопределённости; неизвестные остаются пустыми.
Не оценивать недостающую ошибку по остатку прогноза.

Проверяющий создаёт `holdout/v1/freeze.json` со следующими полями:

```json
{
  "commit_sha": "<exact SHA prereg-v1>",
  "reviewer": "<идентификатор независимого проверяющего>",
  "predictions_precede_disclosure": true,
  "observations.csv_sha256": "<sha256>",
  "conditions.csv_sha256": "<sha256>",
  "predictions.csv_sha256": "<sha256>",
  "model_derivatives.csv_sha256": "<sha256>",
  "prediction_metadata.json_sha256": "<sha256>"
}
```

Значение true — фактическое подтверждение порядка, не формальная заглушка.
Хеши можно вычислить локально через `shasum -a 256 holdout/v1/<имя файла>`.
Синтетический freeze репетиции не подтверждает реальное раскрытие.

## 5. Проверка и сохранение результатов

```sh
uv run --locked --no-sync python scripts/validate.py
test "$(git rev-parse HEAD)" = "$(git rev-parse 'prereg-v1^{commit}')"
test -z "$(git status --porcelain --untracked-files=all)"
```

Выход — `reports/validation/validation.json`. В нём `comparison_groups.full`,
`.conditional`, `.not_testable` и причины; `within_conditional_tolerances`
показывает численное прохождение. Условные сравнения не называются валидацией;
полный вердикт требует полного бюджета. Нулевой код означает, что процедура
выполнилась, а не прохождение научных критериев всеми моделями.

До чтения наблюдений `validate.py` вызывает тот же `require_freeze`, что прогноз
и воспроизведение: exact HEAD тега, отсутствие staged/unstaged изменений и
новых неотслеживаемых научных файлов в защищённых путях. Затем обязательны
все хеши freeze, внутренние хеши метаданных, статусы и согласованные идентичности
прогнозов/производных. Debug-пакет не допускается даже с корректными внешними
хешами и декларацией проверяющего.

Игнорируемые файлы не сохраняются в Git автоматически. Руководитель архивирует
весь пакет holdout, freeze, отчёт, паспорт, summary, карты и большие выборки с
SHA-256 в отдельном хранилище результатов до очистки checkout. При публикации
проверить лицензии/приватность и перенести разрешённые артефакты в отдельную
ветку отчёта после завершения замороженной цепочки; её HEAD уже не prereg-v1.
Не использовать `git add -f` для продолжения расчёта на другом HEAD.

## Репетиция T020

Только в отдельном временном клоне с проверенным snapshot кода/конфигураций:
создать локальные commit и временный `prereg-v1`; реальные V-ветки/наблюдения
туда не переносить. Синтетические условия используют `source_id=synthetic`,
`extraction_id=synthetic-T020` и произвольные наблюдения, не числа из источников.

```sh
make reproduce-full REPRODUCE_FULL_ARGS=--rehearsal
uv run --locked --no-sync python scripts/predict_holdout.py
# Затем независимый синтетический observations.csv и явно synthetic freeze.json.
uv run --locked --no-sync python scripts/validate.py
```

`--rehearsal` фиксирует 2 ветви × 2 повтора × 8 выборок, без карт; и паспорт,
и summary имеют status debug. Проверка exact тега и исходной чистоты остаётся.
C-калибровка не сокращается: те же 64 подгонки и побайтовая проверка frozen YAML.
Прогнозы имеют обычный frozen-контракт для проверки потребителя, но их metadata
также содержит хеш **синтетических** условий; пакет нельзя принимать за реальные V.
Результаты и команды выполненной репетиции — `reviews/T020_prereg_rules.md`.
