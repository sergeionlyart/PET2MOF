## Особенности GPT-6.2, учтённые в инструкциях

* **Остановка ради подтверждения.** При неясном намерении модель может предложить следующий шаг и ждать
  подтверждения [S19]; в `codex exec` с `approval_policy="never"` ответить некому. Общая преамбула
  `scripts/agents/prompt_preamble.md` (добавляется скриптом ко всем заданиям; хеш — в `meta.json`) требует идти до
  сдачи в границах карточки, явно записывать обратимые допущения и останавливаться только на блокере.
* **Краткость по умолчанию и проверка.** Ответы короче [S19]; преамбула требует самодостаточный итог и проход по
  всем пунктам карточки перед сдачей. Для финальной проверки длинных задач OpenAI рекомендует более высокий effort.
* **Субагенты.** Codex 0.166 предлагает GPT-6.x инструменты collaboration (`spawn_agent` и др.) и без `ultra`;
  ни `features.multi_agent=false`, ни `--disable multi_agent` их не убирают (проверено T060). Запрет — в преамбуле,
  а контроль — по rollout: `actual.agent_tool_calls`; при значении > 0 запуск не учитывается (exit 4). Аудит
  всех 68 прежних запусков: ни одного вызова.
* **Контекст и стоимость.** Astra в Codex — 272 k токенов по умолчанию, Sol — 500 k. В API запрос длиннее 272 k
  входных токенов тарифицируется выше [S15, S16]; большие входы карточек не увеличиваем без нужды.
* **Срезы знаний.** Astra — 18.05.2026, Sol — 01.06.2026 [S15, S16]; сведения о литературе после среза — только из
  источников с сетью и `extraction_id`.
* **Effort.** Уровни разных поколений не полностью сопоставимы [S13]; начальные уровни ниже не повышаются
  автоматически при смене модели. `none` у GPT-6.2 API не принимает [S15, S16]; в проекте он и не используется.

## Правила назначения effort

* Стартовый уровень — по сложности и цене ошибки, не максимальный (S18: «самый лёгкий уровень, который проходит критерии приёмки»): `low` — механические задачи;
  `medium` — сбор/проверка информации, обычный код; `high` — научный анализ, безопасность, модели;
  `xhigh` — только если принятый результат на `high` требовал существенных исправлений.
* `ultra` запрещён (автоделегирование делает фактические модель/настройки непрослеживаемыми).
* Экономия оценивается по качеству принятого результата и времени исправлений (журнал ниже).

## Фиксация фактических настроек

JSON-события `codex exec --json` модель и effort **не раскрывают** (только `usage`). Фактически
применённые клиентом значения берутся из записи `turn_context` rollout-файла
`~/.codex/sessions/**/rollout-*-<thread_id>.jsonl` (`scripts/agents/actual_settings.py`) и
сохраняются в `private/agent_logs/<task>.*.exit.json`; публичная сводка — `reviews/agent_contributions.md`.
Ограничение изоляции: `--ignore-user-config` не отключает глобальный `~/.codex/AGENTS.md` владельца; его указания
(например, о Linear) могут попадать в контекст исполнителя. Карточки проекта явно указывают, что Linear не используется.
Ограничение: это настройки, применённые и отправленные клиентом; маршрутизация на стороне сервера
не наблюдаема. Самоотчёт модели о своём имени ненадёжен и не используется.
