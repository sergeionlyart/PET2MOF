# Методология инфраструктуры T005

## OCR

Сначала используются исходные таблицы, CSV/JSON, SI и авторские данные, затем текстовый
слой PDF с постраничной проверкой. `OCRAdapter.extract(..., mode="local", purpose=...)`
по умолчанию извлекает текст PyMuPDF. `method="pdftotext"` использует установленный
`pdftotext -layout`; `method="tesseract"` распознаёт только явно выбранные страницы,
отрисованные в 300 dpi. Автоматического выбора страниц по метрикам нет. Доли повреждённых
символов и цифр, возможные колонки — сигналы для просмотра исходной страницы, не критерии
верификации чисел. Нумерация PDF и публичная `api_page_map` начинаются с 1.

Настройки читает модуль `ocr.config`, вызываемый адаптером: только корневая `.env` либо
явно переданный путь; без импорта/экспорта окружения. Построчный разбор принимает ровно
allowlist карточки T005. Не поддерживаются shell-подстановки, многострочные значения и
`export`. JSON сервисного аккаунта хранится одной строкой, удобно в одинарных кавычках;
также допустима JSON-экранированная строка в двойных кавычках. Файл владельца не создаётся.
`readiness()` возвращает статусы и фиксированные причины, не значения настроек.

Платный запрос разрешается только при одновременном выполнении условий:

1. `OCR_EXTERNAL_ENABLED=true` и выбран `mistral` или `google_docai`.
2. Бюджет `OCR_BUDGET_USD`, число страниц `OCR_PAGE_LIMIT` и цена
   `OCR_PRICE_USD_PER_PAGE` строго положительны и конечны. Лимит страниц — целое число.
3. Авторизация выбранного сервиса и модель/версия процессора заданы.
4. В ledger достаточно бюджета и страниц для очередной попытки.

Неизвестная цена, отсутствующие значения и нули запрещают платные вызовы. Отсутствующая
`.env` означает локальный режим независимо от переменных окружения. Ключ сам по себе
не разрешает расходы. Явно запрошенный внешний режим при запрете выдаёт исключение.
В этой задаче расходы не разрешены, внешние вызовы не выполнялись.

Google JSON проверяется по типу, совпадению проекта и разрешённому token endpoint.
Credentials создаются в памяти. ADC допускается как уже настроенная альтернатива;
проверка готовности запрещает сетевое обнаружение ADC и не проверяет права удалённого
процессора. Поэтому наличие credentials не доказывает удалённую работоспособность.
Google требует фиксированную версию процессора. Для Mistral псевдоним `latest` допустим
только с фактической версией из ответа; иначе ответ сохраняется приватно, а операция
завершается ошибкой. Облачные библиотеки импортируются лениво, устанавливаются отдельно:

```sh
UV_CACHE_DIR="$PWD/.uv-cache" uv sync --locked --extra ocr-cloud
```

Перед отправкой `selected_pdf` собирает в памяти новый PDF только из выбранных страниц.
Области и преобразования входят в интерфейс ключа кэша; отправка отдельных вырезанных
областей пока не реализована. Исходный файл и конфигурация целиком в запрос не включаются.

`private/ocr_cache/ledger.json` блокируется `flock`; обновление атомарное. Резерв:
страницы × цена. Неопределённый сетевой сбой и каждый повтор учитываются как оплаченные;
не более двух повторов, всего до трёх попыток. SDK-повторы Google отключены. Освободить
резерв можно только при определённой отмене до отправки. После падения процесса
незавершённые резервы сохраняются. Ошибка авторизации и превышение лимита блокируют
дальнейшие платные попытки в ledger; восстановление требует ручной проверки, не
автопереключения сервиса. Изменение лимитов не сбрасывает расходы. Перед новым этапом
владелец должен согласовать период бюджета и сохранение прежнего ledger.

Raw JSON пишется один раз с правами `600` и атомарно публикуется по хешу. API кэша
отказывается перезаписывать существующий файл. Очистка `sanitize()` создаёт отдельное
представление: удаляет служебные credentials, заголовки, идентификаторы аккаунта и URL,
маскирует зарегистрированные секреты, подписи URL и блоки ключей в тексте. Фильтр журнала
обрабатывает также форматированные аргументы и текст исключения. Произвольные новые поля
провайдеров требуют повторного аудита; перед публикацией нужен ручной просмотр (§10.3).
Права файлов не изолируют процессы одного пользователя, см. `security.md`.

SHA-256 входа фиксируется до извлечения; изменение файла во время подготовки выявляется
повторным хешированием. Хеш в результате и ключе кэша сохраняет идентичность отправленного
входа, даже если файл изменился во время сетевого ожидания. Исходные файлы по правилам
проекта всё равно должны оставаться неизменными.

## Происхождение и единицы

Паспорт извлечения валидируется по `data/extraction/schema/extraction.schema.json`;
схема также включается в wheel. Неизвестное указывается явно (`null`/`unknown`, где
разрешено схемой), а не заменяется догадкой. `verified` требует имени проверяющего.
`require_measurement()` запрещает авторские подгонки, симуляции и непроверенные записи.
`provisional` допускается только вместе с `allow_provisional=True` и `sensitivity_only: true`.
Создание паспорта не выполняет независимую научную верификацию.

Для CO2 используется молярная масса 44.0095 g/mol; STP по умолчанию — идеальный газ
при 273.15 K и 1 atm, 22414 cm³/mol. Для иной конвенции передаётся
`stp_molar_volume`. `wt%` означает граммы CO2 на 100 g сухого адсорбента.
Загрузка PEI в нормировке — массовая доля PEI в композите, не отношение PEI/MOF.

Оцифровка поддерживает две точки калибровки на каждой оси, линейную и log10 шкалы,
включая перевёрнутую ось пикселей. Сохраняются хеш изображения, точки калибровки,
пиксели маркеров, тип серии, пиксельная ошибка и версия кода. Погрешность — локальное
распространение ошибки считывания первого порядка. Неопределённость калибровочных точек,
поворот и перспективные искажения не учитываются. Их нужно оценивать отдельно.

## Запуски и локальные проверки

```sh
make env
make test
make test-ocr
make publish-check
uv run --locked --no-sync python scripts/run.py --name example --purpose "smoke" \
  --hypothesis "infrastructure only" --allow-dirty -- python -c "print(1)"
```

Последняя команда создаёт только отладочный запуск. Для учитываемого расчёта убрать
`--allow-dirty` и начать с чистого зафиксированного дерева. Параметры передаются JSON-файлом
через `--parameters`: каждое значение содержит `value` и `unit`. Дополнительные входы/выходы
объявляются повторяемыми `--input`/`--output`; сохраняются относительные пути и SHA-256.
`seed` записывается; установить seed конкретного движка должен сам расчётный код.
Секреты в аргументах и метаданных запусков запрещены. Обёртка маскирует распознаваемые
credential-флаги в паспорте, но это не заменяет запрета передавать ключи через командную строку.
Вывод процесса остаётся в приватных журналах; неудачные запуски сохраняют паспорт.

Тесты запрещают сетевые соединения и используют только синтетические PDF и фиктивные
маркеры. Временные файлы pytest и uv находятся в `.uv-cache/`. Внешние библиотеки
не нужны для локального пути. `reproduce-demo`, `reproduce-full`, `report` пока возвращают
код 2: научный расчёт и отчёт реализуются следующими этапами.

Проверка публикации сканирует tracked и publishable untracked файлы; выводит правила
и пути файлов, но не содержимое совпадений и не вывод сканера. Зарезервированные
почтовые домены RFC 2606 (`example.com`, `example.org`, `example.net`, `*.test`,
`*.invalid`) допустимы для примеров. Остальные адреса требуют noreply GitHub.

`.gitleaks.toml` расширяет стандартные правила gitleaks. Исключения для публичных
идентификаторов NIST ISODB и ключей цитирований Crossref требуют одновременно
совпадения пути и полного шаблона match; правило generic-api-key остаётся включённым.
Один конфиг применяется к рабочему дереву (временной копии публикуемых файлов),
staged и **всем** git refs, включая ветки других worktree.

`configs/publish_allowlist.yaml` содержит точные записи `{path, check, reason, sha256}`
для проверенных определений шаблонов и описаний правил в карточках. Исключение
касается только указанного текстового правила и действует при совпадении SHA-256
всего файла. Изменение файла возвращает FAIL при наличии срабатывания; обновление
хеша требует повторного ревью. Эти записи не отключают gitleaks. Исключения не
добавляются автоматически. История и чужие ветки этой задачей не изменяются.
