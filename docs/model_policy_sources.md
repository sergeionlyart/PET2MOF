## Модели

**GPT-6 Astra** [S9, S10, S13]. OpenAI описывает её как наиболее способную для самых требовательных задач: сложные рассуждения, код, работа с компьютером, исследования и документы. В API поддерживаются `low`, `medium`, `high`, `xhigh`, `max`; значение по умолчанию на странице S10 не указано. Примеры S9: `low` для краткого текста и адаптации содержания, `medium` для масштабных проектов с широким контекстом, `xhigh` для сложного анализа и результатов со строгими требованиями. Для Codex и ChatGPT Work S13 предлагает начать с Light (`low`) и повышать усилие по необходимости. API: контекст 1 050 000 токенов, максимум вывода 128 000, срез знаний 30 апреля 2026 года.

**GPT-6.1 Sol** [S9, S11, S13]. Для сложного программирования, работы с компьютером и профессиональных задач; OpenAI характеризует её как близкую к Astra по качеству сложной работы при меньшей стоимости. В API поддерживаются `low`, `medium` (по умолчанию), `high`, `xhigh`, `max`. S9 приводит `medium` для сложной технической работы и согласованных материалов, которые предполагается дорабатывать, `xhigh` — для проработанных материалов и решений по противоречивым данным. S13 рекомендует начать с уровня по умолчанию в клиенте и менять его по задаче. API: контекст 1 050 000 токенов, максимум вывода 128 000, срез знаний 30 апреля 2026 года. В Codex и ChatGPT Work контекст по умолчанию 500 000 токенов; вызов инструментов в API требует Responses API.

**GPT-6.1 Terra** [S9, S12, S13]. OpenAI описывает быструю модель для визуального анализа, работы с компьютером и текста; примеры — технические чертежи, экраны приложений, написание и редактирование текста. S9 также предлагает ограниченные исправления кода и сравнение с Sol на одинаковых входах и уровне усилия с проверкой результата. В API поддерживаются `none`, `low`, `medium` (по умолчанию), `high`, `xhigh`, `max`. S9 не задаёт отдельный рекомендуемый уровень Terra; применимы общие рекомендации S13 и S14 ниже. API: контекст 1 050 000 токенов, максимум вывода 128 000, срез знаний 1 июня 2026 года. Вызов инструментов требует Responses API; веб-поиск поддерживается в Responses API. Для Terra в Codex CLI требуется версия 0.159.0 или новее [S13].

Для всех трёх страниц моделей заявлены текстовый вход и выход, вход изображений, поддержка веб-поиска через Responses API; аудио- и видеовход на страницах моделей не поддерживаются [S10–S12]. Эти API-спецификации не следует автоматически переносить на все интерфейсы Codex.

## GPT-6.2 (добавлено 17.11.2026, руководитель)

**GPT-6.2 Astra** [S15, S17–S20]: «наиболее способная» модель для самых трудных проектов от начала до конца —
изменений по существующей кодовой базе, исследований, документов. API: контекст 1 050 000 токенов (вход до
922 000), вывод до 128 000, срез знаний 18 мая 2026 года; текст и изображения на входе. Уровни effort и значение
по умолчанию на странице модели не перечислены; `none` API отклоняет. В Codex контекст по умолчанию 272 000
(до 1 млн через `model_context_window`); в кэше моделей Codex — `low`…`ultra`, по умолчанию `low`. S18: `low` —
готовая работа по ясному заданию, `medium` — планирование и выполнение сложных проектов, `xhigh` — открытые
задачи с взвешиванием компромиссов.

**GPT-6.2 Sol** [S16–S18, S20]: основная модель для повседневной работы, кода и агентов; на том же тарифе позволяет
выполнить больше задач, чем GPT-6.1 Sol [S20]. API: те же контекст и вывод, срез знаний 1 июня 2026 года, `none`
отклоняется. Codex: контекст 500 000 по умолчанию, `low`…`ultra`, по умолчанию `low`. S18: `medium` — исправления
и новые функции в существующем коде, черновики документов; `xhigh` — многошаговые задачи с тестами и доработкой.

**Указания по переходу** [S19]: ответы короче и прямее по умолчанию; при неясном намерении модель может
предложить шаг и ждать подтверждения — для долгих задач нужно дать ей право на разумные допущения; указывать
результат и решения, требующие пользователя, разрешать продолжать в границах задачи; просить полную проверку
каждого пункта перед завершением; для кода — описывать соглашения репозитория, переиспользовать существующую
логику. Для новых интеграций начинать с `medium`. S18: выбирать самый лёгкий уровень, проходящий критерии
приёмки, и сравнивать модели на одинаковых входах с учётом времени проверки и исправлений. Отдельного руководства
по переходу с GPT-6/6.1 и минимальной версии Codex CLI для GPT-6.2 источники не дают; запуск на 0.166.0 проверен
T060. Terra версии 6.2 в источниках нет.

## Выбор усилия

По S14 меньший `reasoning.effort` обычно уменьшает задержку и расход токенов; более высокий даёт модели больше возможностей для рассуждения. Поддержка уровней зависит от модели. Общие примеры OpenAI: `low` — поиск, планирование и многошаговые решения с учётом скорости и стоимости; `medium` — исследования и задачи, где важны качество и суждение; `high` — сложные рассуждения и глубокое планирование; `xhigh` — глубокое исследование и длительные агентные задачи, когда проверки показывают пользу, оправдывающую затраты; `max` — самые сложные задачи. Для `none` приведены задачи, чувствительные к задержке и не требующие рассуждения; поддержка зависит от модели.

Для Codex и ChatGPT Work S13 советует начинать с доступного в клиенте уровня по умолчанию и повышать его для более глубокого анализа. Light/Low подходит для быстрых ограниченных задач, Medium балансирует скорость и глубину, High и Extra High — для сложной работы с несколькими шагами или источниками. Max увеличивает время рассуждения одной модели; Ultra использует субагентов для параллельных частей задачи и не является синонимом API `max`. По правилам проекта Ultra запрещён. S13 предупреждает, что уровни разных поколений не полностью сопоставимы. S9 рекомендует экспериментально сравнивать модели и настройки на собственной задаче.

## Чего источники не устанавливают

- Страницы не гарантируют достоверность научных расчётов, извлечённых чисел, цитат или интерпретаций и не подтверждают пригодность любой модели для автономной научной проверки.
- Поддержка инструмента веб-поиска у Terra не доказывает полноту поиска или точность нормализации источников в PET2MOF. Эта карточка создаёт материал для независимой сверки, а не сравнительный эксперимент Terra и Sol.
- API-уровни не доказывают доступность тех же уровней в конкретной установке Codex. Наличие `max` в API не означает разрешение проектом на `ultra`.
- Запрошены `gpt-6.1-terra` и `medium`; фактические модель и effort текущего запуска интерфейс исполнителю не раскрывает. Факт запуска через проектный скрипт из доступного контекста также не подтверждён.
