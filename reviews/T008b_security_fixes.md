## Публикация и ограничения среды

Обычный вызов `make publish-check` здесь сначала отказал с `git-index-readable`:
sandbox запрещает запись `index.lock`/Git-объектов в служебный каталог основного checkout,
который расположен за пределами writable root. Это ограничение среды, а не успешная проверка.
Для проверки фактических изменений создан альтернативный индекс `.uv-cache/publish-index`
и хранилище `.uv-cache/publish-objects`, с исходными Git-объектами только для чтения через
`GIT_ALTERNATE_OBJECT_DIRECTORIES`. В альтернативный индекс явно добавлены только изменённые
файлы задачи, отчёт и обновлённые SHA-исключения. Основной индекс не изменялся.

Повторная команда для подготовленного альтернативного индекса:

```sh
env GIT_INDEX_FILE="$PWD/.uv-cache/publish-index" \
  GIT_OBJECT_DIRECTORY="$PWD/.uv-cache/publish-objects" \
  GIT_ALTERNATE_OBJECT_DIRECTORIES="$(git rev-parse --git-path objects)" \
  UV_OFFLINE=1 PYTHONDONTWRITEBYTECODE=1 make publish-check
```

Единственная причина итогового FAIL — ранее известный сторонний публичный токен
в исторических `data/raw/nist_isodb/docs/copyright.html` и
`data/raw/nist_isodb/docs/project.html`. Snapshot индекса, staged-сканирование, собственные
текстовые проверки, SHA-исключения, режимы/ссылки, история запрещённых путей и неизменность
индекса проходят. История не переписывалась. Коммит, push и внешняя публикация не выполнялись.
Перед сдачей нужен независимый read-only вердикт T008c.
