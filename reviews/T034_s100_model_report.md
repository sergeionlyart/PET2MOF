## Результат

Основным описанием остаётся кусочно-линейная интерполяция. На фиксированных 9 точках внутреннего
блока проверки её MAE = **0.02857317776635277**, у Langmuir — **0.13463126273750856**
в сообщённых ммоль/г. Langmuir не уменьшает суммарную MAE; дополнительный флаг неустойчивости
срабатывает для UiO-66. Правило выбора применено без изменения плана.

Источник чисел: пакет `data/task002/PET2MOF_Task002_DataPack_v1.0/`,
`data/benchmark/S100_dry_isotherms.csv`, `metadata/S100_internal_split.csv`;
S100, SI Fig. S5, прежняя оцифровка `T006-S100-FigS5`, 298 K.
Это оцифрованные координаты, не новые непосредственные измерения.
Производные метрики: `reports/task002/B/decision.json`, extraction_id `T034-B-decision`;
параметры: `langmuir_fit.csv`, `T034-B-langmuir-001`…`005`.

Остаток определён как прогноз минус оцифрованная q. Суммарная MAE считается по всем 9 остаткам,
а не как среднее пяти MAE. Улучшение на UiO-66 не меняет суммарного решения; обе его MAE
ниже полуширины 0.105. Для него `q_s=6.32992410 > 3·1.90171371`, поэтому флаг неустойчивости включён.
У остальных Langmuir-флаг не включён. Ошибки параметров — локальная диагностика невзвешенного МНК:
`SSE/(n−k) · (JᵀJ)⁻¹`, вычисленная через SVD аналитического якобиана. Полуширины оцифровки
не используются как SD; ошибки параметров не объявляются экспериментальной неопределённостью.

## Toth и неудачные попытки

У всех четырёх PEI-кривых Langmuir имеет 8 fit-точек и 2 смены знака остатков в порядке давления:
правило подключения Toth сработало. У UiO-66 7 fit-точек, поэтому Toth для него не запускался.
Нули при подсчёте смен знака пропускаются; пороги `n≥8`, `смен≤2` не изменены.

Toth: `q=q_s·b·p/[1+(b·p)^t]^(1/t)`, положительные параметры, невзвешенный МНК.
Использованы логарифмические координаты и аналитический якобиан; при вычислении стандартных ошибок
якобиан переведён к физическим параметрам. Численная граница `log(parameter)≤690` предотвращает
переполнение и не является физическим ограничением.

У 10PEI и 40PEI оптимизатор сообщил успех, но упёрся в численную границу; у 20PEI и 30PEI
успешных попыток нет (лимит 10000 вычислений). Во всех четырёх случаях параметры неустойчивы,
ранг физического якобиана равен 1, стандартные ошибки обозначены `unknown`.
Ни одна подгонка Toth не принята основным описанием. Результаты не обосновывают значения насыщения.
Все 36 попыток, их старты, статусы, причины остановки и SSE сохранены в `optimizer_attempts.json`;
`toth_fit.csv` и `toth_check_residuals.csv` явно отделяют не сошедшиеся итерации от успешной
остановки оптимизатора. Метрики последних итераций — только диагностика.
Дополнительного правила выбора Toth в плане нет, оно после просмотра результатов не вводилось.

Первый незарегистрированный малый прогон с Toth в физических координатах остановился на 10PEI:
ни один из 9 стартов не сошёлся при лимите 10000. Переход к логарифмическим координатам —
численная стабилизация той же формулы, без изменения разбиения или критерия выбора.
Финальный запуск сохраняет все свои успешные и неудачные попытки.

## Чувствительность и описание

`sensitivity.csv`, extraction_id `T034-B-sensitivity-001`…`025`: номинал и четыре отдельных
общих сдвига всех 48 координат, с повторной подгонкой Langmuir по тем же 39 идентификаторам и
проверкой на тех же 9. При сдвиге давления диапазон поддержки сдвигается вместе с точками;
повторное назначение ролей по сдвинутым давлениям не производится. Экстраполяции нет.

| Сценарий | MAE базы | MAE Langmuir |
|---|---:|---:|
| Номинал | 0.02857318 | 0.13463126 |
| q + 0.105 | 0.02857318 | 0.15688577 |
| q − 0.105 | 0.02857318 | 0.12199980 |
| p + 0.042 bar | 0.02857318 | 0.08841063 |
| p − 0.042 bar | 0.02857318 | 0.19550728 |

В каждом сценарии сохраняется база. В CSV приведены также изменения параметров, относительные
изменения, MAE и максимальные остатки каждого образца, флаги неустойчивости.
При общем сдвиге q или p линейные интерполяционные остатки инвариантны с точностью вычислений.
Это детерминированные сценарии полуширин, не доверительные интервалы; деление на √n не используется.
Toth не прошёл диагностику; анализ чувствительности относится к базе и обязательной модели Langmuir.

`S100_nominal_shapes.csv` воспроизводит отношения `q(p)/q(0.85)` для 0.15/0.50/0.85 bar
по всем доступным точкам внутри каждого образца. Разность нормированных значений описывает
ветвь адсорбции; ёмкость цикла из неё не вычисляется.
`descriptive_all48.csv` содержит отдельную подгонку Langmuir по всем 48 точкам с пометкой
«описание, не проверка». Она не входит в выбор или метрики проверки.

## Точная команда запуска

Ниже воспроизводимая команда для bash из корня checkout. Она хеширует входы, код, план,
тесты, описание среды и все 14 выходов. Прямой `make task002-s100` оставляет `debug-unregistered`.

```bash
export UV_CACHE_DIR="$PWD/.uv-cache"
export UV_PYTHON_DOWNLOADS=never
pack=data/task002/PET2MOF_Task002_DataPack_v1.0
input_args=()
for path in \
  "$pack/data/benchmark/S100_dry_isotherms.csv" \
  "$pack/metadata/S100_internal_split.csv" \
  "$pack/reference/S100_internal_baseline_residuals.csv" \
  "$pack/reference/S100_nominal_shapes.csv" \
  "$pack/reference/baseline_summary.json" \
  docs/task002/analysis_plan.md docs/work_order_task002_RU.md \
  src/pet2mof/task002/s100.py scripts/task002/s100_model.py \
  tests/test_task002_s100.py Makefile pyproject.toml uv.lock; do
  input_args+=(--input "$path")
done
output_args=()
for name in \
  S100_internal_baseline_residuals.csv S100_nominal_shapes.csv reproduce_baseline.json \
  langmuir_fit.csv check_residuals.csv decision.json sensitivity.csv descriptive_all48.csv \
  toth_fit.csv toth_check_residuals.csv optimizer_attempts.json curves.png residuals.png provenance.json; do
  output_args+=(--output "reports/task002/B/$name")
done
uv run --locked --no-sync python scripts/run.py \
  --allow-dirty \
  --name task002-B \
  --purpose 'S100: независимая база, Langmuir, условный Toth и чувствительность, T034' \
  --hypothesis 'Минимальная изотерма оценивается по фиксированному внутреннему блоку и правилу плана Б' \
  "${input_args[@]}" "${output_args[@]}" \
  -- .venv/bin/python scripts/task002/s100_model.py --run-id '{run_id}'
```

Выполненный run_id: `20261117T045410127552Z-d95ccb0a-task002-B`. Паспорт: `runs/<run_id>/passport.json`;
сырые stdout/stderr остаются в игнорируемом `private/run_logs/<run_id>/`.
Паспорт фиксирует исходный commit, версии среды, SHA-256 входов/выходов, команду, exit code и ресурсы;
модельные параметры находятся в хешированных CSV, настройки оптимизатора — в коде и `provenance.json`.

Для **учитываемого запуска** руководитель после приёмки фиксирует изменения и повторяет ту же команду
из чистого checkout, удалив только строку `--allow-dirty`. До запуска
`git status --porcelain --untracked-files=all` должен быть пустым; после проверить `status=completed`,
`execution_status=completed`, `exit_code=0`, 14 выходных хешей и `reproduce_baseline.passed=true`.
Поле `registration_status_at_generation` в provenance — статус паспорта на момент работы дочернего
процесса; окончательный статус находится в паспорте.
