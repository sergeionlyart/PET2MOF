Неопределённость исходного сообщения об экспериментальной ошибке не истолкована как стандартное отклонение.

В новых CSV сохранены точные списки колонок `docs/holdout_schema.md`; отдельные статусы находятся в `T019b-series-status.json`, причины также есть в `conditions.notes`. `conditions.csv` не содержит наблюдаемых ёмкостей. Независимость общих знаменателей и калибровочных ошибок не предполагается. Паспортный `provisional` и флаги сравнения имеют разный смысл.

Воспроизведение из текущего каталога:

```sh
export UV_CACHE_DIR="$PWD/.uv-cache"
uv sync --locked
uv run --locked --no-sync python scripts/extraction/fetch_holdout_v1.py
uv run --locked --no-sync python scripts/extraction/extract_holdout_v1.py
uv run --locked --no-sync python scripts/extraction/check_holdout_v1.py
make test-ocr
git diff --check
```

Fetch проверяет SHA-256 каждого исходника, включая PDF внутри SI-архива; HTTP-отказ или другой хеш останавливает получение. Сеть не нужна для сборки после получения исходников. `T019b-build-metadata.json` фиксирует дату операции; повторная сборка сохраняет её и не выдаёт новую дату за новую проверку. Исходные PDF/изображения/overlays находятся в игнорируемых `data/raw/pdf/` и `private/`; проекты содержат их хеши. Неудачные обращения к источникам сохранены в `T019b-access.json`; осмотр исходных страниц и уточнение собственного алгоритма — в `T019b-source-review.json`. Изменение порога основывалось на видимых контурах, не на остатках к модели или контрольным координатам.

Предварительный `git diff --check` выявил CRLF стандартного CSV-writer; экспорт переведён на явный LF. Неудачная проверка и её причина сохранены в `T019b-checks.json`, полный вывод — в `private/T019b/checks/4.log`. Это изменение окончаний строк, не корректировка наблюдений. Для частичных символов серия в проекте содержит консервативный максимальный `sigma_pixel`, а точные индивидуальные границы считывания записаны отдельно и используются в CSV.

Для T019v2 руководитель сначала передаёт **только** `T019b-source-only-manifest.json` и указанные первоисточники в отдельную рабочую директорию без CSV/проектов/отчётов T019, T019b и T019v. Проверяющий сохраняет собственные исходные координаты, калибровки, параметры алгоритма, оценки ошибок и SHA-256 checkpoint; руководитель фиксирует checkpoint до выдачи экспортов. Затем выдаётся текущий результат T019b для сопоставления. Этот отчёт также относится ко второму этапу. После раскрытия исходные проекты не перезаписываются: исправления сохраняются отдельно и явно помечаются. Сам пакет не доказывает, что такая процедура уже выполнена.

Назначенных `.agents/skills`/`.claude/rules` и целей `card-start/gate/gate-plan/prove` в checkout нет; они не имитировались. Прямое поручение задаёт локальную работу без commit. `.env` и секреты не читались; платные сервисы, CI, PR и публикация не использовались. `make publish-check` не запускался, поскольку commit/push не выполняются. Тесты завершились с существующими предупреждениями PyMuPDF/SWIG; это не предупреждения о научной верификации.
