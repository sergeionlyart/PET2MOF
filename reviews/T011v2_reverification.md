## Способ контрольной оцифровки

Инструмент — локальные `prepare.py`, `geometric_check.py`, `summarize.py` в
[`T011v2-control/`](../data/extraction/digitization/T011v2-control/).
PyMuPDF 1.27.2.3, OpenCV 4.13.0, NumPy 2.4.2, Pillow 12.1.0, Python 3.11.5.
Для просмотра выполнен рендер PDF; для измерения использованы исходные пиксели встроенного
растра без дорисовки. Увеличение для просмотра не добавляет разрешения.

Квадраты измерены по направленным горизонтальным/вертикальным границам длиной ≥3 px:
направление белой стороны позволяет отличить левый край от правого и нижний от верхнего.
Центр вычислен из края и размера изолированного символа легенды; наклонная линия подгонки
не служит опорой. Треугольники — геометрическое сопоставление видимых границ с тремя отрезками,
круги — с окружностью; печатные шаблоны и их корреляция не используются. Для цветных символов
перекрытия другими цветами исключены из внешней границы. Сохранены все использованные
пиксели границ, поисковые окна, размеры опорных символов и контрольные центры в четырёх
`*.project.json`. Шаг геометрического поиска — 0.5 native px.

Линейная калибровка повторно определена по длинным границам рамок; у S106 нулевое давление
находится внутри рамки, поэтому x-калибровка получена по подписанным делениям 0.2 и 0.8.
Оценка неопределённости: геометрические диапазоны локализации + 1.5 native px калибровки;
для квадратов дополнительно 0.5 px геометрии размера. Для слабых кругов проверены радиусы
8.75±1 px, перекрывающие разброс размеров изолированных кругов, и три цветовых порога.
Диапазоны при RMS ≤ лучший RMS +0.75 px являются диагностикой неоднозначности, не
статистическими доверительными интервалами. Проверяется реалистичность **суммарной** ошибки
экспорта, а не точность эксперимента. Единственный оптимум шаблона сам по себе её не доказывает.

## Сохранность 12 прежних серий и пригодный диапазон

Сравнение выполнено с историческим коммитом **447364e5f59c962f73d46125263617886d49dbb1** —
состоянием до T011b, полученным через `git show`, без доверия к контрольным хешам самого T011b.
Все 12 перечисленных T011v серий совпадают по числу строк, порядку и буквальным байтам каждого

**Полные CSV побайтово НЕ совпадают:** status изменён `provisional` → `verified`; дополнительно
в исходных T011 CSV окончания строк изменены CRLF → LF. В 12 обработанных CSV обе версии

побайтово неизменным файлом. Поэтому буквальную формулировку «12 серий побайтово не изменились»
можно принять только применительно к явно выделенному блоку числовых полей, но не полным файлам.

с суммарными границами, 19/19 серий и 806 строк согласованы, 12/12 числовых блоков сохранены.
